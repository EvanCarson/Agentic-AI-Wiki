# Ch 14: Judgment Under Pressure (`judgment-under-pressure`)

Part III · The Craft · phase-num 14 · 3,500–4,500 words.

## Argument (bible §5)
Judgment is knowing which commitments are load-bearing. The threshold, the data path, the sponsor
and the exit matter; almost everything else is negotiable.

## p.goal draft
> Under pressure, most FDEs defend the wrong things: features and dates, while the threshold and
> the data path quietly give. Hold four commitments, trade everything else, and put each "no" in writing.

## STEPs
- **14.1 Judgment is a short list.** Employers ask for it in vague words (OpenAI FDE + manager
  posts, Glean "Builder's judgment"; T4 as what employers ask for). Thin evidence stated up front:
  the T2 material is Stanford enterprise-AI rescues, not FDE judgment. Sceptic: "judgment" is the
  word for what nobody measures. Working definition: knowing which commitment, if it gives,
  takes others with it.
- **14.2 The four load-bearing commitments.** Threshold, data path, sponsor, exit; what breaks if
  each gives. Relation to Ch 13's five conditions (diagnosis vs. the moment of pressure).
  Stanford logistics "80% is perfect for us" (T2): the threshold's value is the owner's to set;
  its existence isn't negotiable. RAND priority switching + "50 percent" (T1); RAND one-year
  commitment ("not worthy" wording). Stanford recruiting rescue (T2): changed only load-bearing
  things; technology "the easiest part". What is negotiable: dates of demos, features, UI, model,
  order of work, which failure category first.
- **14.3 Composite.** Week 3, shadow-run live. Claims director asks for write-back and property
  in the week-4 readout. FDE says no to both, yes to three negotiables. Cites ch6/7/8 patterns.
- **14.4 How to say no so it holds.** Structure: the commitment it breaks, the cost in their words,
  the alternative, the trigger, the decider. Sierra "every big technical discussion is also a
  negotiation… hold your ground" (T4). Sceptic: same post's "Drive financial success for both the
  customer and Sierra" — a no can be margin protection; the test.
- **14.5 "Can you promise it will never…?"** Determinism request (situation 26). Promise in code
  what code can enforce (link Ch 10); promise a measured rate and a verification path for the rest.
  Morgan Stanley via ZenML (T3): "the technology is probabilistic", verification tools for lower
  confidence, 4 months of trust.
- **14.6 Not every alarm needs action.** OpenAI manager post "distinguish what requires action"
  (T4). Rechat/Lucy whack-a-mole (T4, no outcome metric). RAND bottom-up: chasing new tools (T1).
  The model is negotiable.
- **14.7 Who backs your no.** Reporting line shapes the no. China: Tencent product family, ByteDance
  R&D and FDE interns under 销售-销售支持 (T4 via iFanr/36Kr); Beijing policy 驻场共创 (T2 policy text).
  Pragmatic Engineer "IT services mindset" → link Ch 12.
- **14.8 Template:** the "say no" note, blank + filled (claims director write-back + property).
- **14.9 Signals you are negotiating the wrong thing** (threat-grid).
- Closing tip.
