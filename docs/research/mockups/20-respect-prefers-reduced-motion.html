Mockup: Respect prefers-reduced-motion for smooth-scroll and CSS transitions

Rank #20 · Tier P2 · Lens: seo-perf · Impact M · Effort S
Before — current guide.css (scroll-behavior and transitions, no reduced-motion guard)
/* guide.css line 24-25 */
html { scroll-behavior: smooth; }   /* ← always on, no guard */

/* guide.css line 93 — nav-part transition */
.nav-part { transition: all 0.15s; }   /* ← no guard */

/* guide.css line 146 — subnav-link transition */
.subnav-link { transition: all 0.15s; }   /* ← no guard */

/* guide.css line 469 — code-tab transition */
.code-tab { transition: all 0.15s; }   /* ← no guard */

/* guide.css line 639 — page-nav-btn transition */
.page-nav-btn { transition: background 0.15s; }   /* ← no guard */

/* site.css line 107 — xref transition */
.xref { transition: color .12s, border-bottom-color .12s; }   /* ← no guard */
After (proposed) — @media block appended to guide.css (and/or site.css)
/* Existing rules above are unchanged. The block below is appended. */

+ @media (prefers-reduced-motion: reduce) {
+   html { scroll-behavior: auto; }
+
+   *, ::before, ::after {
+     animation-duration: 0.01ms !important;
+     animation-iteration-count: 1 !important;
+     transition-duration: 0.01ms !important;
+   }
+ }

User impact: users who have enabled “Reduce motion” in their OS (macOS: System Settings › Accessibility › Display › Reduce motion; Windows: Settings › Ease of Access › Display › Show animations) will no longer experience smooth-scroll on anchor links or the 0.15 s hover transitions on nav parts, subnav links, code tabs, prev/next buttons, and cross-reference links. This closes WCAG 2.1 SC 2.3.3 (Animation from Interactions) with a single 8-line block appended to the stylesheet — no component changes required.
