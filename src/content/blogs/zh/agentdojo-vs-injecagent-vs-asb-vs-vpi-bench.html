这个季度总会有人告诉你，智能体提示注入的成功率是 27%，或者是 84%，而两人引用的都是真实论文、而且引得没错。这道落差不是分歧，也不是模型方差——它是四个基准在四种不同的攻击面上、用四种不同的成功条件做出的测量。一个不带基准名的攻击成功率不是一个弱的数字；它根本不是一个数字。

把这些标志性数字放到同一根轴上，好让你看清为什么不该这么做

请把这张图读成一份关于基准的诊断，而不是一张风险排行榜。顶上那个 100% 和底下那个 24% 测的不是同一件事。VPI-Bench 的浏览器操作数字，统计的是一个智能体执行了被渲染进某个它被要求去读的页面里的指令，而那种架构直接把攻击者的文字作为一个可寻址节点交给了它。InjecAgent 的 24%，统计的是某个特定模型、在某种特定提示策略下、在单步之内完成了某个特定的攻击者目标。Agent Security Bench 对间接注入的 27.55% 与对混合攻击的 84.30% 出自同一篇论文，相差三倍——这是「攻击的组成决定了那个数字」最干净的一次演示。

实务后果是：当一家厂商告诉你他们的防护把攻击成功率从 X 降到了 Y，第一个问题不是「降了多少」，而是「在哪个基准上、针对哪条通道、以及那个任务怎么样了」。我们在评估护栏与检测器里从防御侧论证过这件事；这篇是同一套论证，只不过是从基准本身上读出来的。

每一个究竟是用来干什么的

AgentDojo——会测量「防御代价」的那一个

AgentDojo 把 97 个用户任务与 629 个安全测试用例铺在四个模拟套件上——一个工作空间、Slack、旅行预订与银行业务——并报告三个数字：良性效用（无攻击时解出的用户任务占比）、受攻击时的效用（用户任务被解出且没有发生对抗性副作用的安全用例占比），以及定向攻击成功率。它用形式化断言去核对最终的环境状态，而不是请一个模型来评判；这件事的重要性超过它听起来的程度：模型评判者本身就可被注入，所以一个用模型来评判的基准，其缺陷与它正在测量的那个缺陷属于同一类。

这套三指标的形状，正是「如果你要交付一项防御、而不是写一篇论文，就先跑 AgentDojo」的原因。一个靠「拒绝一切」把定向 ASR 压到零的过滤器，在任何只报告 ASR 的基准上都能拿满分。AgentDojo 是那个会逼你把拒绝的代价一并公布出来的基准。

InjecAgent——便宜、狭窄的回归测试

InjecAgent 是单步的：一次工具响应承载注入，一个攻击者目标，两种危害类别（直接危害与数据窃取），外加一个在注入指令前加上一段 hacking 提示的增强设定。它在 17 个用户工具与 62 个攻击者工具之上的 1,054 个用例，使它跑得快、形态上完全确定；而它的标志性结果——以 ReAct 提示的 GPT-4 有 24% 的时候被攻击成功，另有一些开放权重模型被报告远高于 80%——作为一次模型比较，如今大体上只有史料价值了。

但它仍然是接进 CI 的头一个正确选择，恰恰因为它狭窄。一个单步基准给你的信号，会在你的清洗逻辑改变时移动，而不会在你的编排改变时移动，而这正是一个回归测试该干的事。把它当单元测试，把 AgentDojo 当集成测试。

Agent Security Bench——那张攻防矩阵

ASB 是四者中最宽的：10 个场景（电商、自动驾驶、金融等）、10 个智能体、400 多个工具、27 种攻击与防御方法、7 项评估指标，并跑在 13 个 LLM 基座之上。论文里最有用的东西是它按攻击类型的平均值：直接提示注入 72.68%，间接提示注入 27.55%，记忆投毒 7.92%，而混合攻击最高，达 84.30%。论文自己对防御侧的结论是：当下的防御效果有限。

请注意这个排序告诉了你什么。直接注入——攻击者控制用户那一轮——成功的频率接近间接注入的三倍，而记忆投毒按次尝试成功得最少。最后那个数字也是最常被误读的那个：一条会持续存在的通道上 7.92% 的单次成功率并不令人安心，因为攻击者可以反复尝试，而一次成功会活过这场会话。

VPI-Bench——另外三个看不见的那条通道

VPI-Bench 把攻击装在渲染出来的像素里：一个网页或应用显示一条恶意指令，而基准同时记录智能体是否尝试了攻击者的动作、以及是否完成了它，共计五个平台上的 306 个用例。真正要紧的那道分野是架构性的、而非关于模型质量的——对从截图出发工作的计算机操作智能体最高 51%，对那些被递上一份已抽取的页面描述、而攻击者的文字在其中已是一等节点的浏览器操作智能体，最高 100%。论文还报告，系统提示类防御带来的改善很有限。

如果你的智能体会截图、或者消费一棵无障碍树，那另外三个基准关于你的主要攻击面什么也没告诉你，因为它们的全部控制与全部攻击都是字符串。我们在视觉提示注入里把这一点算到底，包括为什么一个截图分类器当不了闸门。

几乎没人报告的那根轴，以及几乎所有人都在钻的那一根

四者中有三个把攻击成功率当作标志性指标。只有一个会逼你报告「在攻击运行期间，用户的任务怎么样了」。这种不对称是这场比较里最有用的一件事，因为改善一个 ASR 数字最便宜的办法，就是把智能体做得更差。

拿一个每天处理 2,000 张工单、基线自动解决率 70% 的客服智能体算一遍。一个把定向 ASR 从 8% 砍到 1% 的过滤器看起来非常出色。可如果它同时把解决率降到了 58%，那你就是用每天 240 张被解决的工单——一个季度约 9,000 张，每一张都落进人类队列——换来了每天 140 次被阻止的攻击。在银行业这也许仍然是对的交易，在一个服务台则显然是错的；但除非有人去测了第二个数字，你连这场争论都没法展开。一个只报告 ASR 的基准，从结构上藏起了这笔交易里花钱的那一侧。

同一种不对称也解释了一个值得放在视野里的结果：一项关于工具调用评测的效力审计（arXiv 2607.02577）请专家复核了取自四个工具调用基准的 496 个任务，发现 92 处评分器与人类的分歧，即 18.5% 的错配率。安全类基准并不豁免于这一类问题。而这正是支持 AgentDojo 那项设计选择——用形式化状态断言而不是模型评判者——的论据，也是「不要把任何单一的已发表差值当成你的防御有效的证明」的论据。

常见问题

为什么被报告的攻击成功率会从 24% 横跨到 100%？

因为这四个基准对攻击通道与成功条件的定义不同。VPI-Bench 的 100% 是一个浏览器操作智能体执行了被渲染进页面里的指令；InjecAgent 的 24% 是一个模型、在一种提示策略下、在单步内完成了一个攻击者目标。这道落差是测试台的性质，不是模型的性质。

我该先跑哪一个提示注入基准？

让通道去匹配你的架构。工具输出：AgentDojo。持久化记忆：Agent Security Bench。截图或无障碍树：VPI-Bench。如果你是在交付一项防御、而不是在比较模型，那就从 AgentDojo 开始，因为它除了攻击成功率之外还报告受攻击时的效用。

什么是「受攻击时的效用」，它为什么重要？

它是「用户任务被完成、且没有发生对抗性副作用」的安全用例所占的比例。它重要，是因为降低攻击成功率最便宜的办法就是让智能体更多地拒绝；而一个只报告攻击成功率的基准，分不出一项好防御与一个坏掉的智能体。

记忆投毒比提示注入危险性更低吗？

不是按次尝试数字所暗示的那种更低。Agent Security Bench 报告记忆投毒 7.92%、直接注入 72.68%，但记忆是持续存在的：攻击者可以反复尝试，而一次成功会活得比这场会话更久，不随它结束。

我能跨这四个基准比较分数吗？

不能，而且同一个基准的不同版本之间也不能——BFCL v3 与 v4 就被明确记载为不可相互比较的两套，而这里同样需要这份警惕。请在同一个基准上，拿一项防御与它自己做改动前后的比较。
