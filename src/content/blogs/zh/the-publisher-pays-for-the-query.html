至今为止，每一套关于「智能体网络」的方案，争的都是：当 AI 读你的网站时，谁该收到钱。而 Cloudflare 在 2026 年 11 月 25 日发布的 Search for Agents，悄悄回答的是另一个问题：当 AI 提问时，谁付钱。答案是你。一个开关就把你的域名变成一个检索 API，三个计量表从 12 月 1 日起开始对你的账户走表，而没有任何一个助手公开承诺过会去调用这个端点。

一览

真正发布了什么，用那些决定「要不要打开它」的措辞来写。

属性按公告所述可信度

这个开关做了什么

从 zone 的 Quick Actions（或 API）打开它，会在你自己的账户里创建一个普通的 Cloudflare AI Search 实例，命名为 search-for-agents-<ZONE_ID>，并把你的域名作为它的数据源。AI Search 就是此前叫 AutoRAG 的那个产品，而它的爬虫现在自称 Cloudflare-AI-Search，是 2026 年 2 月从 Cloudflare-AutoRAG 改名而来。这底下没有一样是新的；新的是这层包装。

发现机制是四个 meta 标签

Cloudflare 会把 agent:instructions、agent:endpoint、agent:method 与 agent:documentation 注入它为该 zone 服务的每个 HTML 页面的 head 里。在 Cloudflare 自家的开发者文档——那个参考部署——上，agent:endpoint 写的是 https://developers.cloudflare.com/.well-known/search?q={query}，agent:method 写的是 GET。而 agent:instructions 标签里装的是写给模型看的行文：「Use this search API to find relevant content across this site with keywords or natural-language queries……」。如果你同时也打开了 Markdown for Agents，那么对带 Accept: text/markdown 的请求，这四个字段还会以 YAML front matter 的形式出现在一个 agent: 键之下。

这个设计里有两点值得注意。它是一个 meta 标签，不是 link rel——所以智能体必须先取回并解析一个页面，才会知道这个 API 存在，这意味着第一个请求永远是最贵的那个。另外该端点也接受带纯文本或 JSON 体的 HTTP QUERY 方法，而这是一个由 Cloudflare 的人共同撰写的草案方法；用它，等于赌某个智能体的 HTTP 客户端支持一个大多数客户端都不支持的方法。

它返回的是片段，而这是对的选择

该端点交还的是匹配页面里的 Markdown 片段，每一段带一个相关性分数。它不生成答案。行文由调用方智能体自己的模型来写。这是整个产品里最好的一个决定：它让出版方不必去干「当一个 LLM」这档事，让归属信息附着在每个片段上，并让输出能与智能体检索到的其他东西组合起来。对照一下另一种做法的失效形态：站点代你作答，而幻觉归你。

到底返回多少片段，没有定论。有报道称新实例默认是十个片段；而独立测试者查询 Cloudflare 自家文档实例时，报告的是每次查询五十条结果、约 45–57 KB 的 Markdown，或大致 10,000–12,000 个 token，其中还夹着跑题的命中。两个数字都在流传，而我们无法从 Cloudflare 公开的材料里把它们对上。如果你要打开这个功能，先自己量一遍，再去推算任何人的上下文预算——包括你自己的账单。

钱流错了方向，而这正是新闻

Cloudflare 的公告明确写了有三个计量表：摄入内容、存储索引、以及服务查询，按 AI Search 的定价计费，并受 Workers Free 与 Paid 方案所含额度的约束。AI Search 的计费原定于 2026 年 11 月 1 日开始，随后被推迟；Cloudflare 11 月 2 日的变更日志把它挪到了 2026 年 12 月 1 日，而同一条记录也把默认同步间隔从六小时改成了二十四小时。所以这个功能上的计量表，距本文写作时还有三天就要开始走。

已公布的 AI Search 费率，在免费额度之外，大约是：每百万摄入 token 0.75 美元、每 GB-月存储 2.00 美元、每千次语义混合查询 0.75 美元、每千次全文查询 0.10 美元；而每月免费额度据报为 500 万摄入 token、10 GB-月存储，以及两类查询各 1,000 次。其中摄入那个数字最硬；其余几个我们只在文档摘要里见过，所以请把具体的分币当作参考，把方向当作结论。

因为方向是毫不含糊的。智能体提问，不用付给 Cloudflare 一分钱。而出版方要为「被提问」付钱。The New Stack 的报道把这句放进了标题——站点所有者承担查询账单——而这确实把 Cloudflare 两年来所建的一切倒了过来。正是这家公司推出了一键屏蔽 AI 机器人，接着推出了 pay-per-crawl，其自家文档把下限定在每次成功抓取 0.001 美元，并对不愿付费的爬虫返回 402 Payment Required。整套说法都是「AI 公司应当为内容付钱给出版方」。而 Search for Agents 让出版方掏钱去服务 AI 公司，并且公告里完全没有提到 pay-per-crawl。

你没有的那个上限

把计费方向和访问模型摆在一起，窟窿就显眼了。/.well-known/search 是你域名上一个公开、无需认证的 GET 端点，由你自己的 HTML 替它做广告，并按查询计量。我们找不到任何关于它的速率限制或按 zone 的查询上限的文档。这不是说没有——这是说 Cloudflare 没有公布过一个，而这恰恰是你在打开一个会计费的端点之前最不想读到的那句话。

缓解措施写在公告里，而且是以一句安抚的口吻：使用「受你的域名设置约束（例如你的机器人管理设置……）」。你既有的机器人管理、AI Crawl Control 与 WAF 规则，对这个路径依然生效。请读两遍，因为它两头都割。它意味着你可以用自己本来就有的工具给这个端点限速与划范围——也意味着一个开着激进 AI 机器人屏蔽的 zone，可以打开这个功能，然后把它刚刚邀请来的智能体拦掉。Cloudflare 没有记录它的托管机器人规则默认如何对待 /.well-known/search。请在你自己的 zone 上查，而不是假定。

需求那一侧完全没人签字

下面这部分，应该决定你为这件事投入多少精力。没有任何一个智能体、助手或爬虫被公布为 /.well-known/search 的使用方。不是 OpenAI，不是 Anthropic，不是 Google，不是 Microsoft，也不是 Cloudflare 代表某个合作方。可信的报道与独立的上手实测都指出了这一点，而其中一篇提出了那个显而易见的检验：一个助手在没被告知 URL 的情况下，能不能自己找到这个接口。

这个路径也不是标准。RFC 8615 规定了 /.well-known/ 这个前缀，并把后缀交给一个 IANA 注册表；而在我们能触达的注册表派生清单里，search 并不在其中。所以这是一个标准前缀下由厂商自选的路径——完全合法，而且不携带任何互操作保证。一个支持它的智能体，支持的是 Cloudflare 的惯例，不是一份规范。

先例并不乐观，而且就在手边。llms.txt 是同一个形状的赌注：一个本该被智能体找到的、出版方侧的文件。采纳率随抽样人群剧烈摆动——某项研究里是一次 30 万域名抓取中约 10%，另一项里是 219 个知名科技站点面板中的 57.6%，而后者的作者自己就称这是一个群体数字、不是全网估计。到了有效性那里就更难看了。被报道的发现包括：某个研究月份里有 97% 的 llms.txt 文件收到的 AI 爬虫请求为零；一项 37,894 个域名的对比得出「有该文件 6.8 次引用，无该文件 6.7 次」；以及 Google 明确表示它不使用这个文件。这些数字我们无法追溯到原始数据集，所以请松着拿——但它们所描述的那个模式，即「一个没人去查询的出版方侧惯例」，正是这个产品要去对抗的基础比率。

为什么这份不对称仍然对你有利

然而诚实的读法是：这里的风险形状比它看上去更好，而且恰恰因为计费方向。把两种失效形态都算一遍：

  • 没人用它。你的抓取照跑，你付摄入与存储，而查询计量表基本停在零。Cloudflare 自己的定期同步在 31 天没有收到搜索请求后会暂停，所以连那笔摄入账单都会自行衰减。「猜错了」的成本：小，而且自限。
  • 所有人都用它。你按查询付费，端点无需认证，而且没有公布过上限。「猜对了」的成本：在你给它设界之前是无界的。

这是一个不常见的安排，而且它把团队评估一个免费 beta 的惯常方式倒了过来。该犹豫的理由不是「这东西会失败」。而是：对于「它成功」那个版本，你手上没有仪表；而这台仪表必须在你所期盼的那件事发生之前就装好。

每一行里第一个动作都是同一个，而且十分钟就能做完：给 /.well-known/search 加一条速率限制、给 AI Search 的那几个计量表设一个账单告警，再自己查一次你的端点，看实际回来多少条结果、多少 token。做了这些，剩下的全是上行空间。

常见问题

打开 Search for Agents 会让 AI 爬虫绕过我的机器人规则吗？

不会。Cloudflare 的公告写明使用受你的域名设置约束，其中包括机器人管理，而其抓取服务据报遵守 robots.txt。实际风险跑的是另一个方向：一个开着激进 AI 机器人屏蔽的 zone，可以对外公告一个随后被自己规则拒掉的端点。

智能体查询我的站点时，谁付钱？

你付。那三个计量表——摄入、存储、所服务的查询——全都走在站点所有者的 Cloudflare 账户上，按 AI Search 定价计费，自 2026 年 12 月 1 日起开始计费。而智能体提问，不用付给 Cloudflare 一分钱。

/.well-known/search 是标准吗？

不是。RFC 8615 把 /.well-known/ 这个前缀标准化了，并把后缀交给一个 IANA 注册表，而在我们能触达的注册表清单里没有 search。它是一个标准前缀之上的 Cloudflare 惯例，不带互操作保证。

这个端点返回多少条结果？

没有定论。有报道称新实例默认十个片段，而独立测试者查询 Cloudflare 自家文档实例时报告每次查询五十条、约 10,000–12,000 个 token。在给上下文或开销做预算之前，先量你自己的实例。

这就是换了个前门的 AutoRAG 吗？

基本上，是。这个开关创建的是一个普通的 Cloudflare AI Search 实例——而 AI Search 就是改名后的 AutoRAG——你同样可以把它经 REST 或 MCP 暴露、从 Worker 里绑定，或当成面向人类的搜索框。新的是那套零配置的搭建，以及那个对外公告的 well-known 路径。

打开这个之后，我该把 llms.txt 删掉吗？

没有理由删。它们干的是不同的活：一个是一份供阅读的页面清单，另一个是一个供查询的索引，而 Cloudflare 在自家文档上两样都发布。真正相关的对比是成本，不是冲突——服务一个静态文件是免费的，服务查询不是。
