同样的一千页文档，你把它交给这四个中的哪一个，花费会是零，或者约九十美元——同一份输入横跨两个数量级，这本身就说明它们不是彼此的替代品。而每篇对比开篇都要摆出的那个准确率数字是字符级的，那并不是让检索崩掉的东西：一个把每个字形都认对、却把表格压平成散文的解析器，已经毁掉了答案，同时分数漂亮得很。按结构保真度、以及算力在哪里运行来选，因为这是两个日后不重新处理整个语料就无法反悔的决定。

速览

四个都把文档变成检索流水线所需文本的工具，而其中没有任何两个卖的是同一样东西。

问题之前的那个问题

这四个工具都能从一份干净的单栏 PDF 里抽出文字，如果那就是你的语料，那就挑最便宜的然后别读下去了。有意思的失败住在那 20% 承载了大部分价值的文档里：一份财务报表，其中的数字只有与所在行列的表头联系起来才有意义；一篇双栏论文，朴素抽取会把两栏交错成一团胡话；一张扫描表单，标签与值在空间上紧邻、在语义上不可分割。

在这些情形里坏掉的不是字符识别，而是结构：阅读顺序、表格单元格的拓扑，以及一个标题到达时还是不是标题、还是变成了又一行正文。阅读顺序出错会污染分块边界，于是你检索到的那一块里装着两个不相关想法的各一半。表格被压平会摧毁行列关系，而一个读到压平表格的语言模型，会自信地把错的数字归到错的年份上。标题层级丢失，则拿走了结构感知分块器唯一可用的信号，悄悄把你精心设计的分块策略降级成定长切分。

这正是文档解析文献里表格指标用 TEDS——基于树编辑距离的相似度——而不用字符分数的原因：它把抽取出的表格当作一棵树与真值树比较，于是"把表格塌成一个段落"会被记成它本来就是的那场灾难。这些工具大多会对标的基准 OmniDocBench 覆盖 1651 页 PDF，横跨十种文档类型、五种版式与五种语言，恰恰是因为解析器的表现无法跨文档构成迁移。

Docling——深入

它拿下的是什么

Docling 出自 IBM Research，采用 MIT 许可，现由 LF AI & Data Foundation 托管——这条治理细节比听起来重要，因为它是"一个宽松许可"与"一个背后站着基金会的宽松许可"之间的差别。它已超过 64000 颗 GitHub star，且发布节奏之快，让"固定一个版本"成了你的分内之事，而不是可选的讲究。它的输入清单也早已远远超出 PDF——Office 格式、HTML、EPUB、邮件、图片、LaTeX、ODF，甚至音频与视频——所以"Docling 是窄的那个、Unstructured 是宽的那个"这句老话已经不成立了。

你拿回来的是什么

主要不是 Markdown——而是一个 DoclingDocument，一棵带类型的树，其中章节、表格、图注与插图都是一等节点。这是这份名单上最被低估的一件事。结构感知分块器需要的正是一棵树；而 Markdown 是这棵树的一种有损序列化，之后你还得再解析一遍才能把同样的信息找回来。如果你打算按标题分块、或让一张表格完整穿过检索，那么从一棵树而不是从文本出发，能省下你写第二个解析器的功夫。

它让什么变难

你现在在运维一条 ML 流水线：要缓存模型权重、要做一个 GPU 决定、要固定一个版本，而吞吐量得你自己去调。按页费用是零，运维账单不是——对一份 5 万页的一次性语料，这笔交换明显划算；对每月 500 页，它明显不划算。Docling 在表单与手写体上也不领先，所以一批扫描的手写受理表不是它该打的仗。

Unstructured——深入

它拿下的是什么

它是一项服务，而不是一个库。那个 Apache-2.0 的包会把 PDF、Office 文档、邮件、HTML 与图片统一到一个接口之后切分，外加一个按文档设定的策略旋钮，让你只在需要 OCR 的地方花 OCR 的钱——但你通常在买的东西，是那个替你运行这条流水线的托管平台：带连接器，并且有别人替你值班。那是一个正当的产品，而它与"买一个库"是两笔不同的交易。

你拿回来的是什么

一份带类型的扁平元素列表——Title、NarrativeText、Table、ListItem——每个都带元数据：页码、坐标、父元素 id。父 id 意味着层级是可以恢复的，但你是在重建它，而不是被人递到手上，而这在"你得写并测试多少代码"上是一个真实差别。

它让什么变难

搞清楚你在付什么钱。他们自家目录里的价差才是要注意的：serverless API 起于约每千页 1 美元，而按量付费约为每页 0.03 美元——同一份文档，取决于你从哪扇门进来，贵三十倍。所以要有意识地选那扇门。技术那一侧，扁平元素列表意味着层级要靠你自己重建；而表格保真度是他们自家公开基准最坦诚的地方：简单表格 100%、复杂表格 75%。后面那个数字，才是预测你那批财务报表的数字。

LlamaParse——深入

它拿下的是什么

让一个视觉模型去看那一页。在那些击败规则式抽取的版式上——密集表格、双栏学术论文、阅读顺序属于视觉判断的幻灯片——一个看得见渲染结果的模型，掌握着文本抽取器没有的信息。它还能把延迟在不同文档体量间保持得大致平坦，而当解析位于面向用户的路径上而不是一个夜间批处理里时，这一点很要紧。

你拿回来的是什么

按页的 Markdown，表格渲染为 Markdown 或 HTML，另可直接针对你提供的 JSON 形状做抽取——当你已经知道自己要找什么、并希望结构在出口处就被强制而不是事后再解析回来时，这很有用。

它让什么变难

模式就是价格，而价格就是那个论点。从便宜一端约每页 0.003 美元，到搭配顶级模型的 agentic 模式约 0.09 美元，是 30 倍的内部价差，而在你的基准上赢下来的那个模式，往往正是贵的那个。两个后果：一次用最贵模式跑出来的概念验证，在生产量级上撑不过自己的经济性；而一份不点明模式的成本估算，不是估算。一切都在托管侧，所以每一页都会离开你的网络——这件事你的数据驻留评审会比你的检索指标更在意。

Mistral OCR 4——深入

它拿下的是什么

几何与校准。它于 2026 年 6 月推出，返回该页的一份结构化表示：段落级边界框、区块分类，以及逐区块的置信度分数，覆盖 170 种语言。置信度分数是那个差异化的东西，而它出奇地罕见——它是本文这几个里唯一让你能建一条路由规则、而不是建一份指望的输出。

你拿回来的是什么

带坐标、类型与置信度的区块。坐标让你能引用一个源区域而不是一整页，而这就是"这个说法来自第 14 页"与"一处读者一眼就能核对的高亮"之间的差别。对任何要在文档之上做接地回答的产品，这是一项真实的功能。

它让什么变难

它的形状是 OCR 的，不是文档模型的：你得到的是对页面上有什么的一份出色描述，而在"把它变成一棵文档树"上帮助较少，于是重组的工作落在你身上。标准价每千页 4 美元、批处理 2 美元、带标注 5 美元，它在价格上居中——比 LlamaParse 的顶级模式便宜一个数量级以上，而在自托管旁边则是一笔真实的开支。

横向对比

每一个真正在卖的是什么

把四者摆在同一根轴上并排，它们分得很干净——而且不是沿着营销所暗示的那条线。Docling 卖的是掌控：对算力、模型版本与升级排期的掌控，代价以运维工作计。Unstructured 卖的是掌控的反面，而且它有意如此：一个 Apache-2.0 的库确实存在，但产品是一条带连接器、有别人值班的托管流水线。LlamaParse 与 Mistral OCR 都是按页卖给你一个托管模型，区别在于递回来什么——LlamaParse 瞄准的是一份成品 Markdown 文档，Mistral OCR 瞄准的是对物理页面的一份准确描述。这样读下来，你真正在二选一的，通常是 Docling 对某一个托管方案，而不是四个工具。

公开的排名彼此矛盾，而这就是那个发现

去找一个冠军，你会找到好几个。2026 年的一份对比把 Unstructured 排第一、LlamaParse 第二、Docling 第三，而 Mistral OCR 远远在后。另一份报告说 Docling 在复杂表格抽取上达到 97.9%。Unstructured 自家的基准页面报告简单表格 100%、复杂表格 75%——这个落差比其中任何一个数字都更能说明问题。在 OmniDocBench 上，专门构建的"OCR 加表格"流水线在表格结构上约得 82 TEDS，而通用视觉语言模型落在 71–74 附近，而另有评测指出：随着版式变难，每一种方法的阅读顺序准确率都会退化。

这些结果无法被调和，而试图调和是个错误。它们是在不同文档构成上做的测量，其中好几份由对结果有利益的一方发布，而解析器的表现是你的文档的函数——这一点与模型基准不同。唯一能预测你结果的排名，是你在自己最糟的五十页上做出来的那个——而把它建起来是一天的工作，不是一个研究项目：拿五十份你的用户真的会来抱怨的文档，手写表格真值，然后用 TEDS 给每个解析器的表格打分。以上的一切，只是"你该先测哪两个"的先验。

会留下来的那个决定，和不会的那个

价格与质量都会挪动：模式会新增、价格会下调，一次新模型发布会在一个季度内重排准确率表。有两样东西在这个时间尺度上不动。第一是运行位置——算力是否跑在你的硬件上——因为把它解开意味着重构一条摄入路径，而不是改一行配置。第二是你所存之物的形状。如果你的流水线现在就承诺了扁平文本，那么日后要加上结构，就意味着按那时的价格把你曾摄入过的一切重新处理一遍；而如果它承诺的是一棵树，换解析器就只是换一下而已。这种不对称，正是"按输出形状而不是按本月基准来选"的理由，也正是让更换嵌入模型如此昂贵的那同一种不对称。

常见问题

视觉语言模型总比规则式解析器更好吗？

不是，而且它输的场合是可以预测的。在干净、格式一致的文档上，一条版面模型流水线更快、更便宜、也更确定，而且它不会把一个看似合理的数字幻觉进一个它读不出来的单元格。视觉模型挣回自己价格的地方，是那些阅读顺序属于判断题的版式。

与模型推理成本相比，按页价格真的重要吗？

它在摄入量级上重要，而不在查询量级上。解析是每份文档一次性的成本，但语料往往很大——一百万页按 0.09 美元是 9 万美元，按 0.002 美元是 2000 美元，而同一份语料自托管则是一周的 GPU 时间。它在你每次重建索引时也重要，而你重建的次数会比预期的多。

在这里我需要对许可有多小心？

比仓库上那枚徽章所暗示的更小心，而这份小心该花在依赖树上，而不是最顶层。Docling 是 MIT，Unstructured 是 Apache-2.0，两者都平平无奇——但一个文档解析器会拉进 OCR 引擎、PDF 渲染器与视觉模型，它们各有自己的条款；而 Unstructured 仓库上曾有一个（现已关闭的）issue 指出的正是这件事：一个 Apache-2.0 的包底下坐着采用 AGPL-3.0 或更高版本与 LGPL 的传递依赖。无论你选哪个自托管解析器，请对你实际启用的那些已安装 extras 做一次许可扫描，而不是对你 clone 下来的那个仓库。

那 Marker、MinerU、Reducto 或某家云厂商的文档 AI 呢？

都在同一片空间里，尤其 Marker 与 MinerU 该和 Docling 并列进自托管短名单。这里选这四个是为了横跨那几根轴——自托管对托管、广度对深度、文档树对页面几何——而不是宣称它们是唯一选项。

我能在一条流水线里混用多个解析器吗？

能，而且常常是对的答案：给那 80% 干净的文档走一条便宜的路，其余走一条贵的路。这正是逐区块置信度分数最好的用途——按它而不是按文件类型来路由，于是贵的那个解析器只看到真正需要它的页面。

分块策略在多大程度上取决于解析器？

几乎完全取决于它。结构感知分块需要有结构可感知，所以一个丢掉标题层级的解析器，会静默地把你的分块器降级成定长切分。如果你正在同时选解析器与分块策略，先选解析器。
