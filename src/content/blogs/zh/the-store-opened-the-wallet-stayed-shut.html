沃尔玛的 Agent Gateway 准许获批的智能体去搜索、去下单，只扣下了一样东西：卡。智能体永远拿不到支付卡信息，也不能新增或更改支付方式——而整场智能体商务之争一路指向的那个定局，就是这条线，而不是摆在它前面的那台 MCP 服务器。如果你造的购物智能体需要亲手保管支付工具，那你是在为一项还没有任何大型零售商授予过任何人的许可而造。

一眼概览

四种立场，在大约一个月之内先后表态，而表态的公司跑的基本上是同一套技术。

平台日期对外部智能体的立场卡在谁手上
沃尔玛（及山姆会员店） 2026-10-21 Agent Gateway，一台 MCP 服务器，面向获批企业与开发者的 beta 在沃尔玛手上——从不交给智能体
亚马逊，买家侧 2026 年 9 月 切断 Meta 的 Muse 智能体；理由是安全、隐私与智能体不标明身份 无授权可谈
亚马逊，卖家侧 2026-09-23 向外部智能体开放 Seller Central API 不是一条购买通路
Target 据报道，2026 年 10 月 一份获批供应方名单 在 Target 手上

这个网关实际授予了什么

两个动词，不是三个

把这份授权读成一串动词，它清晰得异乎寻常。智能体可以搜索库存，也可以购买——对着顾客已经存档的某个支付方式提交订单。它不可以持有：没有任何卡片信息到它手上，而「新增或更改支付方式」那条路对它是关着的。建在这个网关上的购物智能体，是一台非常好的选品引擎外加一个提交按钮，顾客的金融关系没有任何一部分经过它。

争议处理这条路从另一头告诉你同一件事。即便智能体的行为不符预期，照常适用的也是沃尔玛的普通退货流程——这是一次不张扬但后果很大的归属分配：零售商吸收了智能体出错的成本，而不是把它推给智能体开发方或顾客。这种选择，只有在你把整笔交易留在自己轨道里时才做得出来；而这也正是这套安排稳当到可以向外开放的原因。

标明身份是入场的代价

审批是一道关口，不是一道手续；关于这次发布的报道称，不遵守条款的智能体将被禁止访问该站点。面向顾客的 Agent Profiles 据报道将在 2026 年 11 月跟上——如果真按描述上线，就意味着顾客能看见是哪个智能体在行动，而零售商拿到了一个可以逐智能体限速、审计或吊销的把手。把这个跟亚马逊切断 Muse 时给出的理由对照看：没有恰当标明自己身份的智能体。两家公司在优化的是同一个属性。只是目前只有一家相信，外部智能体可以被要求提供它。

亚马逊用同样的技术画出了相反的线

这才是值得坐下来琢磨的部分。这两个案子之间没有任何技术差别。两家零售商都在 API 后面跑着庞大的目录；都能看见一次请求的来处；只要它们愿意，都能给第三方智能体做注册。亚马逊在 2026 年 9 月切断了 Meta 的 Muse 智能体，并在 2025 年 11 月因 Perplexity 的 Comet 浏览器智能体在其商城下单而起诉对方；而就在封掉 Muse 的两天之后，它向外部智能体开放了 Seller Central API——我们在《亚马逊在同一周里打开了后台、关上了店面》里写过这件事。

变量是一个商业判断：一个站在零售商与顾客之间的中介，算渠道还是算竞争对手。对一家靠搜索位、广告和自有品牌商品赚钱的零售商来说，一个会执行「帮我买最便宜的同类品」的智能体是去中介化的威胁。对一个挑战者来说，同一个智能体是它不用花钱买的流量。全部差别就在这里；而这是一个每当商业理由发生变化就会被重新评估的判断。

协议能让一个集成变得可行。它不能让这个集成变得被允许——而「被允许」这部分，是带着续期日期的。

所以「我们用的是官方 MCP 服务器，所以是受支持的」才是那句出现在故障之前的话。一个官方端点告诉你的是：平台造了一扇门。它不告诉你你的钥匙下个季度还转得动。我们把对应的工程回应写成了《平台对智能体访问的条款》：一页依赖表、一个「触发即停而非重试」的鉴权形状失败指标，以及一条把真实购物车还给用户的降级路径。

如果你在造购物智能体，这件事改变了什么

按「挑选」去设计，别按「保管」去设计

你产品里耐久的那个版本，是在平台愿意下放的那一部分上做到卓越：听懂一个含糊的请求、把它在真实目录里解析清楚、对替代品做出判断、组出一个人类认得出来的购物篮。脆弱的那个版本，是把差异化建在「持有凭证」上——替人自动填卡、存一个钱包、在别人的库存上充当记录商户。到目前为止每一条公开的封禁理由，瞄的都正是后面这个形态。

假设审批是逐零售商的，并把集中度定价进去

「获批智能体」这种模式意味着你的覆盖图是一张关系清单，每一条都有自己的复核、自己的条款，以及自己可被单方面终止的出口。如果某一家零售商承载着你在自己营销里立下的一条承诺，那就是一份工程修不掉的集中度风险。要么握住第二条获认可的通路，要么在产品里把这份依赖说明白。

在任何人开口之前，先让智能体变得可被读懂

在请求里标明智能体身份、保留能证明「是哪个人要求了这次行动」的同意记录、遵守公布的速率，并保留平台会去查的那些核验信号。正在开放的那些平台都在搭建审批流程；一个本来就像「已获批」那样行事的智能体，走的是一次简短的复核，而不是一场艰难的辩论。相邻的实操页是《购物与结账智能体》。

把被封当成策略事件，不是错误

权限被收回时的样子是：昨天还能走的那条路由返回 403，或者过去给 JSON 的地方变成一张挑战页。笼统的重试逻辑会把它读成暂时性故障，于是把一个策略决定变成对一个刚刚叫你停下的平台的重试风暴——一个本可挽回的误会，就是这样变成永久封禁的。按平台单独统计「鉴权形状」的失败；一旦封禁持续，就安静下来并呼人。

还没有定下来的那部分

卡的保管权现在算是相当清楚了。还有三件事不清楚。意图的归属：当智能体买错了东西，「顾客要的是日用杂货」并不构成一份「同意了这个篮子、这个价格」的记录，而整个行业没有一种共用的格式来表达它——《AP2 与智能体商务》里的协议工作就是在尝试。比价与位次：一个放智能体进来的零售商，放进来的是一个可能在会话中途被指向竞争对手的东西，而目前还没有任何公开条款说明智能体可以拿它看到的价格做什么。规模：一个按人类购物行为定容的网关，碰上了一个每小时就把篮子重新比一遍价的智能体——而为浏览器写的限流会是最先崩掉的东西。

这三件事都是穿着技术戏服的商业争论，和当初那个「卡」的问题一模一样。预期它们会以同样的方式被解决——写在条款文件里，参差不齐，由各有各自理由的公司分别决定。

常见问题

沃尔玛的 Agent Gateway 是一台 MCP 服务器吗？

是——发布报道把它描述为一台 MCP 服务器，获批的智能体通过它在沃尔玛与山姆会员店搜索库存并下单；截至 2026 年 10 月 21 日的公布，它处于面向企业与开发者的 beta 阶段。

通过这个网关的智能体能看到或存下顾客的卡吗？

不能。智能体永远拿不到支付卡信息，也不能新增或更改支付方式。订单是对着零售商已经持有的某个支付工具提交的——而整套安排正是围绕这条边界搭起来的。

为什么亚马逊封了智能体，沃尔玛却放它们进来？

不是技术原因。亚马逊在 2026 年 9 月切断 Meta 的 Muse 时援引的是安全、隐私与智能体未标明身份，但底层的变量是：一个处在零售商与顾客之间的中介，被当成渠道还是竞争对手——这是一个因公司而异、而且会变的商业判断。

如果智能体下错了单，谁负责？

在沃尔玛的网关上，即便智能体的行为不符预期，适用的也是零售商的普通退货流程。这是一次有意把智能体出错成本分配给零售商的安排；而它之所以可行，正因为这笔交易从未离开它自己的轨道。

今天我该把什么造得不一样？

按「挑选」而不是「保管」去造；假设审批是逐零售商、且可被单方面终止的；在每一次请求里标明你的智能体身份；并且把「鉴权形状」的失败单独埋点，这样一次封禁会让你的流量停下，而不是把它放大。
