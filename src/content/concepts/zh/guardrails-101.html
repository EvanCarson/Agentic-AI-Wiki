B9
概念 · 核心构件

用大白话讲护栏。

Meta 自己的论文给出的数字是：它的提示词注入分类器在 1% 误报率下召回 88.7%；而一份独立基准测出同一个模型在注入藏进工具输出（而不是由用户打出来）时，召回落到 1% 上下。两个数字都是真的，而它们之间的落差就是全部的教训：护栏是一个带工作点的分类器，不是一堵墙，所以它的强度永远只能表述为「在我真能承受的误报率下，有多少漏过去」。也正因如此，唯一一道绝不该是概率性的检查，是守在不可逆动作前面的那一道。

STEP 1

护栏是你自己拥有的一道检查，不是模型的属性。

人们说「这个模型有护栏」时，其实在说两件不同的事。一种是实验室训进权重里的内建行为：模型倾向于拒答某些提示词。那是模型的属性——有用，但不是你能掌控的，而且换模型它就没了。另一种才是本篇要讲的：一段你自己写的代码，包在一次模型调用外面。输入在模型看到之前先过一道预检；输出在被你的应用使用之前先过一道后检；工具调用在真正执行之前先过一道动作检查。模型本身没变——你只是给它装了一圈闸门。

这个区分要紧，因为两者的失效方式不同。内建拒答会被精巧的提示词越狱，那是你没法排进日程的研究问题。包在外面的检查则以朴素、可修的方式失效——正则写错了、分类器训练不足、规则漏了一条。好消息是：朴素的失效正是你能修的那种。坏消息，也是本页剩下大半篇幅的主题：大多数「包在外面的检查」本身就是模型，而护栏里的模型会继承你本想防住的每一条性质。

一个好用的检验：如果你的「护栏」在换一个模型之后就消失了，那它从来不是护栏——那是你指望的某种模型属性。真正的护栏是你拥有的代码，坐在模型外面，换模型也照样在。

STEP 2

它们可以待的三个位置——而只有一个能说「不行」且当真。

生产环境里每一道护栏，相对那次模型调用都坐在三个位置之一，大多数系统三处都用：

  • 输入护栏跑在模型之前。它拒掉或改写进来的东西：拦住看起来像注入的文本、在请求送达提供方之前抹掉 PII、拒绝已知禁止的类别。便宜，而且能让你不花一次模型调用就失败。
  • 输出护栏跑在模型之后。它在应用使用补全前先检查：丢弃不安全输出、抓住泄漏的机密、拒掉任何通不过 schema 校验的东西。
  • 动作护栏跑在模型提议的工具调用与真实副作用之间。这个目的地在白名单里吗？这笔金额在日额度以下吗？这一类写入有人批过吗？

这三者不可互换，原因不在它们坐在哪，而在它们做的是哪一类判断。输入和输出检查问的几乎总是语义问题——「这段文字是攻击吗？」「这个答案有害吗？」——而语义问题由分类器回答，也就是由概率回答。动作检查可以问结构性问题：这个确切的字符串在不在这份确切的清单里，这个整数是否小于那个整数。这种检查的误报率在构造上就是零，它不会被话术说动，而它是整个栈里唯一一层「不行」不等于一个置信度分数的地方。其余都是分诊。

所以分层是真的，但不对称。输入过滤把流量变稀；输出检查接住模型自己的失误；而真正把损害圈住的是动作检查，也正是你应当不愿意把它做得「聪明」的那一道。总体形状见引用监视器，那份清单如何维护而不沦为橡皮章见自动批准与白名单。

STEP 3

要读工作点，不要读那个头条分数。

护栏厂商公布的是 AUC——那是跨所有阈值的一个汇总量，而它恰恰不告诉你你真要上线的那一个阈值如何。你需要的数字是一对：在某个明确的误报率下的命中率。Meta 的 LlamaFirewall 论文（2025 年 5 月）给出 2200 万参数版 Prompt Guard 2 的英文 AUC 为 0.995、1% 误报率下召回 88.7%、多语言 AUC 为 0.942，每次分类约 19 毫秒；8600 万参数版两项都更高，也更慢。把这一对数字照面值接下来，算一算它在你的流量上意味着什么：

20,000 checks/day, 1% FPR, 88.7% recall, 50 real attempts/day

  false blocks     19,950 benign x 1%    = ~200 legitimate requests blocked/day
  missed attacks   50 x (1 - 0.887)      = ~6 attacks through/day
  caught           50 x 0.887            = ~44

tighten the threshold to catch 5 more:
  recall 0.887 -> 0.98 costs roughly 5-10x the FPR
  false blocks     ~1,000-2,000/day      = the product is now broken

这段算账掉出两件事。第一，每天 200 次误拦已经是一条工单队列，所以决定这东西能不能上线的是误报率、不是召回率；你真正的工作点由用户能忍到哪里来选定，命中率只是剩下的那部分。第二，阈值是一个带旋钮的产品决定，所以它该和决策模型阈值放在同一场对话里，而不是放进一次安全评审。

接着是更难的那一半：那个 88.7% 是在某个分布上测出来的，而你的分布不一样。一份可复现的第三方基准用 AgentDojo 式的注入做测试，报告 Prompt Guard 2 在默认阈值下、当注入是藏在工具输出里而非出现在用户轮次时，对 629 次攻击的命中率约在 1% 的量级；把阈值重调到 2% 的误警预算后，在未见过的领域上升到约三分之一。这里没有任何矛盾——同一个分类器，不同的输入分布，不同的阈值——但它确实意味着：一个公布的召回数字要能迁移到你的系统，前提是你的攻击面长得像那个评测集。对智能体来说通常并不像，因为危险文本来自一个被检索到的网页或一次 API 响应，而不是来自正在打字的人。在你自己的流量上把这件事测出来，是评估护栏与检测器的主题。

STEP 4

面对一个读过你防御的攻击者，这个数字会挪动一个数量级。

以上全部假设攻击按一个固定分布到来。真实攻击会适应。在《The Attacker Moves Second》（Nasr、Carlini、Sitawarin、Tramèr 等，2025 年 10 月；USENIX Security 2026）里，作者重新评估了十二种已发表的越狱与提示词注入防御，横跨四个族系——提示法、对抗训练、检测器模型、秘密知识检查——而这次允许攻击者针对每种防御的设计量身调整手法，并投入真实的优化算力。这些防御中大多数原本报告的攻击成功率接近零。在自适应攻击下，多数超过 90%。检测器模型比其余几族撑得久一些，也仍然被打穿：论文对其中之一报告了 71%。

这篇论文自己的排除项才是其中最有用的一句话。作者没有纳入那些在读到不可信内容之前就把智能体的计划钉死的设计，因为这些攻击大体改不动这种智能体会做什么。这就是整个发现的另一种说法：检测的效力随攻击者对你的检测器了解多少而缩水，而约束不会。过滤器是对文本的一个猜测；白名单是关于能力的一个事实。

所以关于输入护栏，诚实的说法很窄，但仍然值钱：它抬高随手试和自动化尝试的成本，它给你一个可以告警和限流的信号，它买来时间。不诚实的说法是它让这一类攻击消失。请按「每一道概率性检查终将被通过」来设计，然后问：到那时智能体还能做什么——这正是爆炸半径要回答的问题。

STEP 5

那到底该建什么。

真正站得住的形状是：概率性的那部分分两级，其余的部分设一道硬止。

  • 先便宜分类器，再昂贵策略。一个几十毫秒的小检测器把所有流量分诊，一个更慢、懂策略的模型来裁定它标出来的那些。这不是省钱手段——OpenAI 描述自己内部就是这么做的：把 Safety Reasoner 与更小更快的分类器配对做分诊。那个 reasoner 的开放权重版本 gpt-oss-safeguard（2025 年 10 月，120b 与 20b）在推理时把策略当文本传进去，而不是把它烘进权重，这是这个品类里唯一一项真正的进展：你可以改一条策略而不必重训一个分类器。
  • 宽泛的分类器就买，具体的规则自己建。别想在毒性或 PII 上训得比实验室好；也别指望买来的护栏懂你工作流里「已批准」是什么意思。你的白名单、你的上限、你的 schema、你的审批类别——这些是你的，而它们才是圈住损害的那些。被「买」的那一半的产品级对比见Lakera Guard vs Prompt Guard 2 vs Prompt Shields vs ProtectAI DeBERTa 与NeMo Guardrails vs Guardrails AI vs Llama Guard vs LLM Guard。
  • 先定好「检查失败了怎么办」。一道超时就被跳过的护栏不是护栏；一道在瞬时错误上就 fail closed 的护栏是一次故障。逐道检查来定，写下来，并且测它——见fail closed 与 fail open。
  • 能撤掉能力的地方，就别去过滤请求。Meta 的「智能体二选二法则」（Agents Rule of Two，2025 年 10 月）是这件事的紧凑版：在同一个会话里，一个智能体最多只该同时具备「不可信输入」「可访问敏感数据」「能改变状态或对外通信」中的两项。砍掉三者之一是结构性的修法，任何分类器精度都替代不了。它命名的那个失效模式就是致命三件套。

这三件事一次坐下来就能做完。写下你在跑的每一个分类器所声称的命中率和误报率，然后用上周的量算出每天的误拦次数——如果这两个数你说不出来，你并不知道那道检查在做什么。第二，列出每一个不可逆的工具调用（钱出去了、消息发走了、数据删掉了），确认每一个都由结构性检查把门——白名单、上限、或一个人——而不是由某个模型的意见把门。第三，挑一条不可逆路径，把攻击注进一次工具结果里而不是一条用户消息里；这一个测试告诉你的，比任何厂商基准都多，因为那才是你的智能体真正生活的分布。
