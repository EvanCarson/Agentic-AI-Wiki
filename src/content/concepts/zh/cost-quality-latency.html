概念 · AI 模型与工具生态

如今成本与延迟之间已经有了明码标价的兑换率——同一个模型上就是 4 倍的价格带——于是三角形里只剩质量这一角还得靠你自己去测。

同一次 Claude Opus 5.5 请求，每百万输入 token 要花 2 美元还是 8 美元，取决的只有一件事：你多急着要答案——走 Batch API 半价，开 fast mode 翻倍。成本 / 质量 / 延迟这个三角形里，已经有两角变成了可以直接查表的兑换率，于是真正剩下的问题是任何厂商都替你答不了的那一个：这一步到底需要多少质量。而便宜那一角一旦弄错，咬得最狠：Claude Haiku 5.5 是当前唯一按提示长度计价的模型，一旦某次请求的提示超过 100,000 token，其中每一个 token 都按 5 倍收费——缓存命中的那些也算。

STEP 1

三条轴，其中两条已经标了价。

按档位思考，而不是按参数量。架构、训练数据与后训练的权重不输于规模，多数模型根本不公布参数量，而每家厂商出的其实是同一级阶梯：一个小而快的档、一个均衡的中档、一个前沿档。阶梯才是实用的抓手。截至 2026 年 10 月，Anthropic 公开价目表上的这级阶梯是这样的。

这张表里有两件事比绝对数字更值钱。第一，当前每一档的输出价都是输入价的 5 倍——这个比例已经跨过一整代模型保持不变，意味着任何「要写很多字」的步骤在每一档都贵，换模型救不了它。第二，这级阶梯在你脚下往下滑：Opus 5.5 的 $4/$20 低于 Opus 5 的 $5/$25，而后者又只有 Opus 4.1 当年收费的三分之一。正是这种代际漂移，让「用最大的模型」很少成为一个站得住的默认选项——去年的旗舰能力就是今年的中档，而且今年比去年更便宜。至于为什么你的账单并没有按同样的倍数下降，价格通缩那一篇把它算清楚了。

延迟是两个数字，不是一个：首 token 时延，由对整段提示做 prefill 的开销主导；以及总生成时间，由输出长度主导。交互式产品的生死系于前者，批处理作业只在乎后者。质量则根本不是一个数字——小模型在抽取或分类上可以追平前沿模型，却会在二十步的规划里崩掉。这恰恰是公开排行榜回答不了这个问题、而你自己的评测集能回答的原因。

STEP 2

成本与延迟不再是你得去做工程权衡的事——它已经是一个价格。

这个三角形的经典讲法，把延迟当成模型规模的物理后果：你想更快，就往下挪一档，拿质量去换。决策的形状已经不是这样了，因为同一个模型现在按几种速度在卖。

  • 交出交互性，换 5 折。Batch API 对每个模型的输入与输出都打五折。Opus 5.5 从 $4/$20 降到 $2/$10。模型没有任何变化；你只是为一个异步到达的答案少付了钱。参见批处理与异步推理。
  • 买速度，付 2 倍。Opus 5.5 的 fast mode 标价 $8/$40，对应标准价 $4/$20，换来的是同一个模型上更快的输出。延迟现在有吊牌价了，而这个吊牌是基准价的 100%。
  • 两者合起来，就是质量恒定下 4 倍的价格带。同一个模型上每百万输入从 2 美元到 8 美元，完全由「答案何时到达你有多在意」决定。任何关于该用哪一档的争论，都应该在你决定好自己处在这条带子的哪个位置之后再谈——因为这条带子比某些相邻档位之间的差距还要宽。

缓存是唯一能把成本与延迟推向同一方向的杠杆，因为一次缓存命中省掉了本来要重做一遍的 prefill。倍数是公开的：缓存读取在多数模型上是基准输入价的 0.1 倍，在 Opus 5.5 与 Sonnet 5.5 上是 0.05 倍，在 Fable 5.1 上是 0.025 倍——$10 的基准价对应每百万 $0.25，对你反正要重发一遍的文本来说是 40 倍的折扣。写入则是五分钟缓存收基准价的 1.25 倍、一小时缓存 2 倍，所以五分钟缓存读一次就回本，一小时缓存读两次回本。对一个每一步都重发固定系统提示与工具清单的智能体来说，这是本页上最大的一个数字。机制见提示缓存。

质量是唯一一条没有公开兑换率的轴。这种不对称，就是这个三角形在 2026 年的实际内容：有两条边你可以按已知价格买过去，第三条你只能自己去测。跳过这次测量的团队，最后要么为一个分类步骤付前沿价，要么因为「便宜档真的便宜」而上线了一次质量回退。

STEP 3

便宜那一角里有道悬崖，而智能体会在跑到一半时走下去。

从 4.6 开始的每一个当前 Claude 模型，都按同一个平价对整个一百万 token 窗口计费——用 Anthropic 自己的话说，「一个 900k token 的请求，按与 9k token 请求相同的每 token 单价计费」。例外恰好只有一个，而且正是最便宜的那个模型。Haiku 5.5 按提示长度计价：超过 100,000 token 之后，输入、输出、缓存写入与缓存读取全部跳涨 5 倍。这条规则写得异常具体，而其中每一个分句都要花钱：

  • 提示长度统计的是全部输入 token，包含缓存读取与缓存写入。缓存并不能帮你留在阈值以下——95,000 token 的已缓存前缀加上 10,000 token 新鲜的工具输出，就是一个 105,000 token 的提示。
  • 每次请求各自定价。越过阈值的那次请求照高价收费，即便它的提示大部分都是缓存命中；而在它之前的请求，仍保留它们当时被计的价格。

智能体循环的上下文是单调累积的，所以这不是一个你做一次就定了的模型选择——它是你这一次运行会在某个步数上跨过的一道边界。把它算一遍。假设一段固定的 30,000 token 系统提示与工具清单，每一步追加 4,000 token 工具结果、输出 500 token，共二十步。第 k 步的提示大约是 30,000 + 4,500k 个 token，在第 16 步越过 100,000。

Twenty-step agent, Claude Haiku 5.5, no caching
                          input tokens   rate      cost
steps 1-15  (under 100K)       990,000   $0.10   $0.0990
steps 16-20 (over 100K)        555,000   $0.50   $0.2775
output, steps 1-15               7,500   $0.50   $0.0038
output, steps 16-20              2,500   $2.50   $0.0063

total                        1,545,000           $0.3865

Priced naively at the headline rate:              $0.1595
Actual / estimate:                                   2.4×

估算错了 2.4 倍，而且误差是集中的：二十步里的五步承担了将近四分之三的成本。请注意这里没有说什么。Haiku 5.5 的 $0.3865，仍比把同一个循环跑在 Sonnet 5.5 上便宜大约八倍——便宜档依然便宜。坏掉的是你的预测，以及你账单的形状：正是这件事，让一个被你建模成平直的运行，在第 17 步触响了预算告警。如果你是从每 token 的头条价来预测智能体支出，请看智能体支出预测里能抓住这件事的那套纪律。

STEP 4

这个三角形到底该怎么用。

你不必挑一个全局的点，而所有最强的做法，靠的都是拒绝去挑。

  • 做路由，不要做选择。阈值以下的 Haiku 5.5，输入价是 Opus 5.5 的二十分之一、Fable 5.1 的一百分之一。先把所有请求发给便宜档，在不确定或检测到任务偏难时再升级；真实流量大多是简单的，所以大部分会在便宜路径上解决，只有确实需要的少数去付前沿的价。实现见模型路由。
  • 按步分档，而不是按应用分档。在同一个智能体内部：用小模型做分类与路由，只在真正难的规划步用推理模型，用中档写最终答案。模型选择的单位是「步」。
  • 在悬崖之前压缩，而不是之后。如果你用的是按长度计价的档位，那个阈值就是上下文压缩的硬截止期，而上下文预算就是让你留在它便宜一侧的东西。如果你实在留不住，一个平价档位的总花费，可能比一个便宜档位的 5 倍还要低。
  • 往上调档，绝不往下调。从能通过你评测的最小档位起步，只在它可测地失败的地方往上挪。先用前沿模型、事后再想办法砍成本，是用更差的信息去做同一件事——因为到那时，你手上根本没有「便宜档会表现成什么样」的测量。
  • 按你真正买的单位计价。算每个完成任务的成本，而不是每 token 的成本——在一个智能体循环上，「少写字」与「降单价」并不是同一种折扣，更少 token 还是更便宜的 token 把它写成了闭式；而一次分词器更换可以在没人改动任何价格的情况下移动你的 token 数。

照这个顺序做。在你自己的评测集上定下质量门槛；挑出能过线的最小档位；然后取你的延迟要求允许的那个公开兑换率——答案等得起就走 batch，等不起就开 fast mode，其余情况走标准价；再把固定前缀缓存起来，因为那是唯一能同时改善两条轴的动作。而如果你的便宜档是按提示长度计价的，就把那个阈值当成一份上下文预算，而不是一条计费细则：一个不知道悬崖在哪里的智能体，会在第 16 步找到它。

延伸阅读：如何选模型给出逐任务的清单，智能体成本控制给出循环的算术，小模型与本地模型讲的是每 token 单价归零、取而代之出现一个吞吐上限的那种情形，而给延迟定价讲的是一次延迟改进对付钱的那家业务到底值多少。
