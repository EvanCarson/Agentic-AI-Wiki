一条有人引路的学习路径

如何从头到尾学习智能体 AI（agentic AI）。

一本面向一线工程师的指南，讲解如何构建智能体系统 — 不是那种回答问题的聊天机器人，而是能够规划、调用工具、自我验证，并真正交付给真实用户的软件。本书从大型语言模型（LLM）的实际运作机制讲起，带你用 4 章双 API 代码（Anthropic 和 OpenAI）从零开始编写一个代理循环（agent loop），然后深入大多数同类材料略过的内容：生产环境可观测性（observability）、成本管控、安全（safety）、评估（eval），以及四种各具特色的智能体形态（代码智能体（code agent）、计算机操作（computer use）、研究智能体、多智能体（multi-agent）），最后探讨如何在这个快速演进的领域持续跟进前沿（frontier）。在领域已有定论的地方保持立场，在尚无定论的地方保持诚实。由一位学习者写就，献给所有正在学习的人。

完整学习路径

0 基础知识 先修 · 4 章
0.1LLM 心智模型 ~25 min
令牌（token）才是真正的基本单位。上下文窗口（context window）是有限且对位置敏感的资源。采样是一个分布，而非一个函数。幻觉（hallucination）是四种有名称、可调试的机制。
0.2提示词工程 ~25 min
系统提示词（system prompt）扮演的三个角色（身份、工作流、安全），以及保持三者清晰分离的原则。有教学效果的示例 vs 固化思维的示例。XML 风格结构何时值得引入。预测-测量-决策的迭代方式。实操案例：将一个路由提示词（prompt）的准确率从 71% 调优至 86%。
0.3工具调用基础 ~25 min
工具调用（tool use）的定义与线路格式（Anthropic tool_use vs OpenAI function_call）、并行调用、错误即数据、30 秒内完成追踪（trace）排查。
0.4AI 开发中的异步 Python ~15 min
智能体为何天然异步（I/O 等待）。四种模式（并行分发、超时、TaskGroup、流式输出与后台任务并行）。五个常见陷阱。进阶模式：shielding、背压、异步迭代。
I 构建智能体 4 周 · 4 章
1.1循环 ~25 min
最小可行智能体。无框架。直接感受原语 — 模型 + 工具 + while 循环。
1.2检索与接地 ~25 min
BM25、稠密向量嵌入、混合融合、重排序，以及在此之上的接地验证。
1.3真实的循环 ~25 min
并行工具调用、用于上下文隔离的子智能体、规划、可中断运行。
1.4第一个评估套件 ~20 min
在优化之前先构建评估。这是区分"造过智能体"和"能持续交付智能体"的分水岭。在第 III 部分中进一步扩展。
II 上线 生产 · 4 章
2.1可观测性 ~25 min
OpenTelemetry GenAI 跨度（span）、能在异步环境下存活的结构化日志，以及一个可在本地复现生产故障的回放 CLI。
2.2成本与延迟 ~30 min
输入令牌在多轮对话中累积，是账单的主要来源。提示词缓存（60–80% 的输入缩减）、模型级联（Haiku 负责路由，Sonnet 负责综合）、并行工具调用、流式首 token 延迟（TTFT）控制在 1 秒以内。
2.3安全与护栏 ~30 min
提示词注入（4 个攻击向量）、有界自主性、纵深防御、红队测试。
2.4部署 ~30 min
FastAPI + SSE 用于短时任务，Submit/poll + Redis Streams 用于长时任务。Postgres+Redis 状态拆分。真正会触发的自动扩缩容信号。熔断器、成本上限、运维手册。
III 评估 持续 · 4 章
3.1评估驱动开发 ~25 min
关注增量（delta），而非绝对分数。噪声基线（noise floor）。回归（regression）预算。PR 评论工作流。版本化运行记录。让数字持续上升的那套纪律。
3.2三层评估体系 ~30 min
第 1 层：确定性检查（每次提交，秒级完成）。第 2 层：基于评判者的评估套件（评估套件（eval suite），PR 和发版时运行）。第 3 层：生产遥测（持续监控）。第 3 层 → 第 2 层的反馈闭环。实操案例：三次回归，分别在不同层级被捕获。
3.3LLM 作为评判者 ~25 min
四种偏差（位置偏差、冗长偏差、自我偏好、权威偏差）。双序评判纪律。用 50 个人工标注样本进行校准。版本管理。跨模型系列集成用于发版门控。
3.4基准与 CI ~30 min
诚实解读公开基准（benchmark）（SWE-bench、GAIA、OSWorld、τ-bench）。分数产生误导的四个原因。内部基准：冻结子集模式及其治理。将三层评估转化为每个 PR 反馈的 CI 流水线形态。发版流程：门控、检查清单、回滚、观察。实操案例：一次真实的因故被拒发版。
IV 专项深入 择一 · 4 条路径
4.1代码智能体 ~30 min
代码智能体与众不同的四个特性（状态、验证、有界动作、反馈）。六种工具（read/write/str_replace/glob/grep/bash）。验证阶梯。Skills + Agent SDK + Managed Agents 生态全景。实操案例：真实 bug 修复。
4.2浏览器与计算机操作 ~30 min
截图-动作循环。四种失败模式（点击偏差、识别错误、滚动盲区、对话框盲区）。优先级层次：优先使用 API，仅在无 API 可用时才使用计算机操作。浏览器 vs 操作系统、安全、Anthropic 产品线。实操案例：一个在生产环境稳定运行的 CRM 数据提取工作流。
4.3研究智能体 ~30 min
在生产中胜出的编排者-子智能体架构。努力程度缩放、边读边压缩、引用规范。四维评估（忠实度、覆盖度、来源质量、校准度）。停止条件。实操案例：一次真实的会前简报。
4.4多智能体系统 ~30 min
判断多智能体架构是否必要的四属性测试。三种可落地的模式（编排者-工作者、流水线、对等路由）。协调规范：任务描述、结构化交接、故障处理。双层评估。实操案例：一个真正凭借自身特性赢得多智能体架构的客服系统。
V 前沿动态 保持跟进 · 1 章
5.1下一步读什么 ~15 min
信号与噪声的问题。真正值得关注的来源（实验室、评估机构、个人、会议）。筛选新论文的五问法。可持续的每周节奏。收尾语。

如何阅读本指南

共六个部分，可通过顶部导航栏切换。点击某个部分会在下方展开第二行章节标签页。每章都是独立的教程，包含模拟追踪、双 API 代码块、内联问答，以及末尾的交付物检查清单。每章需要认真阅读约 15–30 分钟；章节标题旁的时间估算是认真阅读所需的时间，而非浏览。

完整路径大约是跨越 22 章、九小时的阅读量。大多数读者不会线性通读。几条常见路径：阅读基础知识 + 构建智能体（约 3 小时）以交付一个可运行的智能体；在面向真实用户上线之前，再加上上线 + 评估（约多 4 小时）；根据智能体形态需要，按需阅读专项深入中的一个或多个章节（每章约 30 分钟）；每季度重温一次前沿动态（约 15 分钟）作为认知校准。

提供两套 API 选项的代码块设有 Anthropic / OpenAI 标签页 — 点击即可切换。页面上所有代码块都会同步到你最后一次的选择。所有模拟输出均是合理的示意，并非字面精确 — 关注结构，而非具体文本。

黄色块是细心读者会提出的问题。深色块是交付物。橄榄色标注是提示；桃色是陷阱；红色是危险。
