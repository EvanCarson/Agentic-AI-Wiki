A learning path · narrated

How to learn agentic AI, end to end.

A working engineer's guide to building agentic systems — not chatbots that answer questions, but software that plans, calls tools, verifies its own work, and ships to real users. The book starts from how LLMs actually work, walks you through writing an agent loop from scratch in 4 chapters of dual-API code (Anthropic and OpenAI), then takes you through the parts most material on this topic skips: production observability, cost discipline, safety, evaluation, the four distinct agent shapes (code, computer use, research, multi-agent), and finally how to stay current as the field moves. Opinionated where the field has converged, honest where it hasn't. Built by someone learning it — for anyone learning it.

The whole path

0 Foundations prereq · 4 chapters
0.1LLM mental model ~25 min
Tokens as the real unit. Context window as a finite, position-sensitive resource. Sampling as a distribution, not a function. Hallucinations as four named, debuggable mechanisms.
0.2Prompt engineering ~25 min
The three roles a system prompt plays (identity, workflow, safety) and the discipline of keeping them distinct. Examples that teach vs ones that calcify. XML-style structure when it earns its place. Predict-measure-decide iteration. Worked example: tuning a routing prompt from 71% to 86%.
0.3Tool use fundamentals ~25 min
Tool definitions, on-the-wire shapes (Anthropic tool_use vs OpenAI function_call), parallel calls, errors as data, trace triage in 30s.
0.4Async Python for AI ~15 min
Why agents are async (I/O wait). Four patterns (parallel dispatch, timeouts, TaskGroup, streaming with background work). Five pitfalls. Advanced patterns: shielding, backpressure, async iteration.
I Build the agent 4 weeks · 4 chapters
1.1The loop ~25 min
Smallest possible agent. No framework. Feel the primitives — model + tools + while-loop.
1.2Retrieval & grounding ~25 min
BM25, dense embeddings, hybrid fusion, rerank. Then grounding verification on top.
1.3The real loop ~25 min
Parallel tool calls, subagents for context isolation, planning, interruptible runs.
1.4First eval suite ~20 min
Build your first eval before optimizing. The thing that separates "built one" from "ships them." Extended in Part III.
II Ship it production · 4 chapters
2.1Observability ~25 min
OpenTelemetry GenAI spans, structured logs that survive async, and a replay CLI that reproduces production failures locally.
2.2Cost & latency ~30 min
Where input tokens dominate the bill, accumulated across turns. Prompt caching (60-80% input reduction), the model cascade (Haiku for routing, Sonnet for synthesis), parallel tools, streaming TTFT under 1s.
2.3Safety & guardrails ~30 min
Prompt injection (4 vectors), bounded autonomy, layered defense, red-teaming.
2.4Deployment ~30 min
FastAPI + SSE for short runs. Submit/poll + Redis Streams for long ones. Postgres+Redis state split. Autoscale signals that actually fire. Circuit breakers, cost ceilings, runbook.
III Evaluate ongoing · 4 chapters
3.1Eval-driven development ~25 min
Deltas not scores. Noise floors. Regression budgets. PR-comment workflow. Version-stamped runs. The discipline that keeps numbers moving up.
3.2Three layers of evals ~30 min
Layer 1 deterministic checks (every commit, seconds). Layer 2 judge-based eval suite (PRs, releases). Layer 3 production telemetry (continuous). The Layer 3 → Layer 2 feedback loop. Worked example: three regressions, each caught at a different layer.
3.3LLM-as-judge ~25 min
Four biases (position, verbosity, self-preference, authority). Both-orderings discipline. Calibration against 50 human-rated examples. Versioning. Cross-family ensembles for release gates.
3.4Benchmarks & CI ~30 min
Reading public benchmarks honestly (SWE-bench, GAIA, OSWorld, τ-bench). The four reasons scores mislead. Internal benchmarks: the frozen-subset pattern and its governance. CI pipeline shape that turns the three layers into per-PR feedback. Release process: gates, checklist, rollback, observation. Worked example: a real release that gets rejected for cause.
IV Specialize pick one · 4 paths
4.1Code agents ~30 min
The four properties that make code agents different (state, verification, bounded actions, feedback). Six tools (read/write/str_replace/glob/grep/bash). The verification ladder. Skills + Agent SDK + Managed Agents landscape. Worked example: real bug fix.
4.2Browser & computer use ~30 min
The screenshot-action loop. Four failure modes (misclick, misread, scroll-blindness, dialog-blindness). The preference hierarchy: APIs first, computer use only for the gaps. Browser vs OS, security, the Anthropic product lineup. Worked example: a CRM extraction workflow that's reliable in production.
4.3Research agents ~30 min
The orchestrator-subagent architecture that wins in production. Effort scaling, compress-as-you-read, citation discipline. Four-dimensional eval (faithfulness, coverage, source quality, calibration). Stop conditions. Worked example: a real pre-meeting briefing.
4.4Multi-agent systems ~30 min
The four-property test for when multi-agent is justified. Three patterns that ship (orchestrator-worker, pipeline, peer routing). Coordination disciplines: task specs, structured handoffs, failure handling. Two-layer eval. Worked example: a support system that earned its multi-agent shape.
V Frontier stay current · 1 chapter
5.1What to read next ~15 min
The signal-to-noise problem. Sources that earn their place (labs, evaluation orgs, individuals, conferences). The five-question triage for new papers. A weekly rhythm that's sustainable. The closer.

How to read this guide

Six parts, navigable from the bar at top. Tapping a part reveals a second row of chapter tabs underneath. Each chapter is a self-contained tutorial with simulated traces, dual-API code blocks, inline Q&A, and a deliverable checklist at the end. Expect 15–30 minutes of careful reading per chapter; the estimate next to each chapter title is what an attentive read takes, not a skim.

The full path is roughly nine hours of reading spread across the 22 chapters. Most readers don't go through it linearly. A few common paths: read Foundations + Build (~3 hours) to ship a working agent; add Ship + Evaluate (~4 more hours) before serving real users; read one or more Specialize chapters as needed (~30 minutes each) when your agent shape calls for it; revisit Frontier (~15 minutes) once a quarter as a calibration check.

Code blocks with two API options have Anthropic / OpenAI tabs — tap to switch. All blocks on the page sync to your last choice. Every simulated output is plausible but not literal — read for structure, not exact text.

Yellow blocks are questions a careful reader would ask. Dark blocks are deliverables. Olive callouts are tips; peach are traps; red are dangers.
