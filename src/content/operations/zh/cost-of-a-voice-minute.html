一分钟语音的成本。

语音是唯一一类账单就是一只时钟的智能体工作负载，而这只时钟同时驱动着四块计价表；至于令牌那块表——唯一一块人人都在优化的——是五块里最小的。这个倒置决定了下游的每一场工程争论：你花在一次确认轮次上的那些秒只要个位数美分，而它们挡掉的那次上报要花掉以美元计的钱——所以该管理的单位是每已解决通话成本，而提升自助完成率撬动它的力度，是砍价目表的好几倍。

STEP 1

一只时钟上的四块表，外加一块按令牌走的。

文本智能体的账单以「工作量」计价：输入令牌、输出令牌、工具调用、沙箱秒数。语音智能体的账单以挂钟时间计价，而同一个挂钟秒，几乎会被技术栈的每一层同时计费一遍。

# What one minute of connected call bills, in parallel
carrier / SIP trunk     per minute      # PSTN leg, inbound and outbound priced apart
platform / orchestrator per minute      # the hosted voice runtime
speech-to-text          per minute      # streaming ASR, usually billed on audio duration
text-to-speech          per character   # or per second of synthesized audio
model                   per token       # the only line that is not a clock

截至 2026 年 10 月，主要托管语音栈公布的平台费大致落在每分钟五到十四美分这个区间里，低端那些数字不含模型与运营商，高端那些则声称包含。请把任何单一的公开数字当作起点而不是报价：头条平台费率与真实的全包费率之间，差上两到三倍是常事——因为头条是一块表，而账单有五块。在把一个数字放进财务模型之前，请到各家厂商自己的页面上核对。

架构上的后果比财务上的来得更早。在文本里，加一个组件，加出来的成本你能在那个组件自己的那一行里看见。在语音里，加一个串行组件会拉长通话，于是四行同时上涨——包括那些你根本没动过的厂商的行。

STEP 2

模型是便宜的那一块，这正是惯常的优化打偏的原因。

把一通电话连同写明的假设算一遍，因为重点是那个比值，而那个比值对确切费率并不敏感。

# One 4-minute call. Assumptions stated, substitute your own.
clock meters   0.12 $/min  x  4.0 min            = 0.480
model tokens   ~20 turns, cached prefix          = 0.020
                                          total  = 0.500

# Share of the bill by lever:
clock          0.480 / 0.500                     = 96%
tokens         0.020 / 0.500                     =  4%

# Halving the model's token price saves 0.010 — two percent.
# Removing one 30-second turn saves 0.060 — twelve percent.

这与文本的情形正好相反：在文本里，上下文膨胀与推理令牌占据主导，而《更少的 token vs 更便宜的 token》里的长期建议，讲的是这两根杠杆该买哪一根。在语音里，这两根杠杆作用的都是账单的百分之四。更便宜、更快、更小的模型仍然值得要——它缩短轮次，轮次缩短则通话缩短，而通话按时钟计费——但它值得要是因为第二个理由，不是第一个；而那些出于第一个理由去挑它的团队，经常是为了省下百分之二而吃下一份准确率损失。

STEP 3

沉默和说话按同一个费率计费。

按分钟的计价表不知道有没有人在说话。来电者在思考、智能体的等待用语、后端调用完成前的空气、问候语、等待音乐、端点检测定时器加在每一个轮次上的那段停顿——所有这些，都被栈里每一块时钟表按「已接通通话」的费率算钱。

这让固定静音超时成了一条费用项，而不是一个用户体验设置。一通二十轮的电话上 700 ms 的端点检测阈值，就是每通电话十四秒的被计费沉默，而且无论来电者是否说完都要付。按每分钟十二美分算是不到三美分——听起来不算什么，直到你注意到它比上面那整块模型账单还大，而且一个基于模型的检测器不用谈判就能把它大部分收回来。机制见《轮次结束检测》。

下面这个区分，化解了它与其余所有关于语音延迟的文字之间表面上的冲突。轮次内部的延迟是一项感知成本；通话时长是一项现金成本；它们是不同的杠杆，而且并不总是同向移动。用一句「稍等，正在调出来」盖住一次两秒的工具调用，改善了前者、恶化了后者。把对话少走一个来回，改善了后者，而对前者可能毫无作用。感知那一侧的定价在《给延迟定价》；工程那一侧是《延迟预算》。本页只谈现金。

STEP 4

质量上的仪式有一个确切的价钱，而且它很小。

语音有个不寻常之处：你能给一项正确性干预标出精确数字，因为这项干预以秒计量，而秒有公开费率。τ-Entity 基准提供了现成最干净的一个算例：一套规定了拼读、复述、纠正与确认的脚手架，把口述实体采集的稳健 Pass3 抬高 14 到 31 个百分点，代价是每通电话 21 到 28 秒。

# Is the confirmation scaffold worth it? Assumptions stated.
scaffold cost        28 s  x  0.12 $/min  / 60   = 0.056   # paid on EVERY call

# What one failed capture costs:
second agent call                                = 0.500
human handling, 6 min at 35 $/h loaded           = 3.500
                                         total   = 4.000   # paid on failures only

# Break-even prevention rate:
0.056 / 4.000                                    = 1.4%

这套脚手架大约要在七十通电话里挡掉一次失败才能回本，而基准测到的是：即便按它区间的低端，它也在七通里挡掉一次。这个余量不接近，而且在团队真正争论的那个维度上差了两个数量级。那句「别加确认轮次，会把电话拖长」的条件反射，定的是分子的价，忽略的是分母。

在为了提速砍掉任何一个轮次之前，用你自己的费率把上面那两个数字算出来。语音流程里几乎每一个正确性轮次，回本门槛都低于百分之三——这意味着问题从来不是这份仪式负不负担得起，而是这份仪式到底有没有挡住那次失败；而那是一个评测问题，不是一个经济学问题。

STEP 5

单位是每已解决通话成本，而上报主导着它。

每分钟成本是一个费率，不是一个单位；而费率没法管理，因为它里面没有结果。能管理的那个单位，正是《智能体单位经济学》在别处一直主张的那一个，只是换成语音的样子：总成本除以真正被解决的通话数，并把上报路径装进分子。

# Cost per resolved call. Agent call 0.50, escalated call 4.00.
containment 60%:   0.50 + 0.40 x 4.00            = 2.10
containment 75%:   0.50 + 0.25 x 4.00            = 1.50    # -29%

# Versus halving every clock meter you pay, at 60% containment:
0.26 + 0.40 x 4.00                               = 1.86    # -11%

十五个百分点的自助完成率，值你把整份价目表砍半的大约三倍，而且它是两者中更便宜的那个——因为它不需要任何一家厂商点头。这道算术还解释了一个从外面看很不理性的现象：有些部署加了轮次、放慢了节奏、确认得更多，结果反而更便宜了。它们动的是分母。

在引用这个数字之前要做两处修正。上报并不是均质的——一次带着上下文、热交接落地的转接，消耗的人工时间显著少于一次让对话从头来过的转接，这正是《上报与热交接》里那笔经济账。另外，一通靠给出错误答案而被智能体「兜住」的电话并没有被解决；它是一次被推迟的上报，外加那个错误答案本身的代价，而这是《出错的代价》的主题。

STEP 6

该测什么，以及你实际在做的那笔交易。

四件仪器，按回报先后排列。

  • 每通电话的被计费秒数，拆开。说话、沉默、工具等待、等待保持。在沉默成为一个单独的数字之前，你看不见栈里最大的那条可回收的线。
  • 自助完成率与上报成本，一起看。任何一个单独拿出来都无法行动；两者的乘积是你账单的大头。
  • 每已解决通话成本看 p95，而不是均值。通话时长是重尾的，理由与智能体任务成本重尾的理由相同，而人工时间就住在那条尾巴里。见《预测智能体开销》。
  • 逐表的费率清单，带日期。五家厂商、五个续约日、五次让一个单位在没有任何发布的情况下改变的机会。记下每一行来自哪一块表。

诚实的交易是：在语音里你没法用钱买质量，只能用时间买——而时间正是账单计价所用的单位，于是每一个正确性决定都成了一笔直接的、可计算的采购，而不是一场关于工程品味的争论。这是礼物，不是约束：它是智能体工程里唯一一处「这值不值？」有算术答案的地方，而答案通常是值。
