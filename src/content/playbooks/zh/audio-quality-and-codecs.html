Playbook · 语音与实时智能体

音频质量与编解码：来电抵达时所在的那个频带，是你的语音模型抬不起来的一道天花板。

一通以 8 kHz 采样的电话在物理上就承载不了 4 kHz 以上的声音，而区分 S 与 F 的大部分线索恰恰住在这条线以上——于是你将来买到的每一个识别器，在一条 PSTN 腿上都有同一个盲区，而模型再好也补不上。音频通路是语音智能体里唯一一个在 ML 团队中无人认领的质量杠杆，而设定它的那个决定，是某家运营商在一次 SIP 握手里协商编解码时做出的。请把频带当作一等部署参数：知道自己收到的是哪一个，别再假装重采样已经把它修好了，并按频带分别度量准确率。

STEP 1

从奈奎斯特开始，因为这道限制是算术，不是模型的属性。

G.711——公共电话网络承载了数十年的 μ-law 与 A-law 这一对——以 8 kHz 采样，为此花掉 64 kbit/s。以 8 kHz 采样，就给可表示频率压上了 4 kHz 的理论硬顶，而实际的电话通带还要更窄，大约 300–3400 Hz。这条线以上的任何东西都永远到不了你的识别器，因为它在第一个数据包离开运营商之前就已经被丢掉了。

这件事之所以要紧，在于住在上面的是哪些音。清擦音与齿音——/s/、/f/、/θ/、/ʃ/——的辨别性能量大多落在 4–8 kHz 区间。电话语音的那些经典失败，恰好就是这些音所区分的那几对：fifteen 对 fifty，S 对 F 对 X，thin 对 fin。当你的转写把它们弄混时，模型并没有在通常意义上犯错；它是从一份已经不再包含辨别线索的证据里，推断出了最可能的那个词。这正是在语音里处理字母数字是一个结构性难题、而不是一个调参问题的原因，也是航空与紧急调度七十年来一直使用标准字母表的原因。

STEP 2

去盘一遍你自己这套栈实际交付的是什么，因为默认值是端到端窄带。

2026 年常见的电话语音智能体，是一个前沿语音模型被喂进 1970 年代水准的音频，而大多数团队从来没有核对过。Twilio 的 Media Streams 是把一通电话接进模型的最常用桥梁，它交付的是 8 kHz 的 base64 G.711 μ-law。模型这一侧，OpenAI 的 Realtime API 接受的要么是一种 μ-law 电话格式——固定在 8 kHz，所以在它上面传采样率参数没有意义——要么是 24 kHz 的线性 PCM；字段名在 beta 与 GA 两种形态之间变过，所以请读当前的参考文档，而不是某篇教程。选电话格式，你的通路就从运营商一直窄带到 token。选 PCM，你就加了一道重采样级——而那和「加了带宽」是两件不同的事。

把这条链一跳一跳明确写下来，每个箭头上都标出采样率。大多数团队这么做之后会发现两件事。第一件是一次他们原本不知道的转码，通常是因为某个提供方在互联点上统一归一到 G.711，哪怕两端本来能说更好的东西——这笔代价在电话网与 PSTN 集成里被算作一道质量损失。第二件是，他们 ASR 厂商准确率宣称里的那个数字，是在一个他们自己的图里根本没有出现过的采样率上测出来的。

# write the band on every hop. the lowest one is your real ceiling.
caller  --[ G.711 u-law  8 kHz ]-->  carrier
carrier --[ G.711 u-law  8 kHz ]-->  telephony API        # ceiling: 4 kHz
tel API --[ G.711 u-law  8 kHz ]-->  your media bridge
bridge  --[ PCM16      24 kHz ]-->  speech model         # upsampled, NOT wideband

# the same path, after negotiating wideband on the legs you control:
caller  --[ Opus     48 kHz ]-->  WebRTC edge             # app/browser callers only
edge    --[ PCM16    24 kHz ]-->  speech model            # ceiling: 12 kHz
STEP 3

重采样满足的是一份输入契约，它不恢复频带。

把 8 kHz 音频上采样到 16 或 24 kHz，产出的是一个形状正确的张量，而且没有增加任何信息——结果里 4–12 kHz 那一段是插值，不是语音。这一点值得平白说清，因为相反的那个信念很常见，而且它承重的方向是错的：一个团队在自己的配置里看到 24000，断定自己在跑宽带，然后就解释不了为什么电话上的准确率远低于基准数字。

还有一重次级代价。实现糟糕的重采样器会引入混叠与镜像伪影，那不只是「信息缺失」，而是主动具有误导性的信息；而每一级转换都会在一个本来就是全系统最难约束的预算上再加几毫秒——见延迟预算。如果你必须重采样，就只做一次、只在一处做、用一个不是你自己写的库，并把你当时用的采样率记录下来，好让后来的对比还能解释得通。

从窄带输入里合成出貌似可信的高频内容的带宽扩展模型，是一个真实的研究方向，而它放在识别器前面是用错了工具。它是把擦音能量发明出来，而不是把它恢复出来——这意味着它能把一个诚实的低置信「S 还是 F」变成一个自信的错误答案。真要用，就用在给人听的回放上，永远别放在通往某个决定的输入通路上。

STEP 4

你真正能拿到的那一次升级，到底在哪里。

宽带选项早已成熟。G.722 以 16 kHz 采样，是在支持它的 SIP 互联上摩擦最小的升级。Opus 覆盖 8–48 kHz，并与 G.711 一起是 WebRTC 中强制实现的编解码——这也是为什么「应用内或浏览器内的来电者」通常是你唯一能以全频带服务的那一类人群。而统辖这一切的规则毫不留情：整条通路以它最窄那一跳的频带运行，所以中间一个 G.711 互联就会让一条本来宽带的路线塌回窄带，而你为其余部分付出的工作一分收益都拿不到。

由此得出一份干净的优先级。你端到端自己掌握的腿——你的移动应用、你的网页组件、你内部智能体之间的音频——应该用 16 kHz 或更好的 Opus，而这通常是一次配置改动而不是一个项目。入向 PSTN 来电，也就是一个客服或外呼拨号产品里的大部分流量，是窄带，而且会一直是窄带；花一个季度去跟你并不掌握的运营商协商 G.722，是这类工作最常见的翻车方式。两件更小的事回报更可靠：避免双重转码，因为一条像 G.729 转 G.711 这样的链路要先解码再重新编码，损失会以两跳各自都预测不到的方式复合；以及把打包时长保持在惯常的 20 ms，因为更大的帧是用延迟去换你并不需要的那点带宽，而更小的帧会放大每包开销与丢包暴露面。

STEP 5

没人能告诉你这个代价有多大，所以请在你自己的通话上测。

公开证据的诚实状况是：很薄。窄带代价最常被引用的那个数字，出自 2014 年一篇 EUSIPCO 研究，它报告采样率从 8 升到 16 kHz 时词错误率有大约 20% 的相对下降——那是两代识别器之前的事，架构也早已无人部署。此后的厂商材料断言宽带有帮助，却几乎从不附上数字；而对你真正要紧的那个数字，取决于你的词汇、来电者的口音、你的噪声底与你的运营商组合。任何你从一篇博客文章里拿来的单一数字——包括这一篇——都是一个猜测。

所以请把频带做成评测里一个显式的维度，而不是一个你忘了记录的常量。用录下来的生产通话、而不是干净的朗读语音来构建留出集，并按编解码、按运营商、按这条腿是否宽带来切分报告词错误率——以及更有用的，任务成功率与实体被听错的比率。方法就是评测语音智能体里那一套；这里加的只是一列。两个结果就够抵回整件事的成本：你会知道自己的宽带腿是否确实可测地更好，从而知道该不该给协商那件事拨经费；你也会停止把一个频带问题归因给模型，然后靠换模型去修它。

为你支持的每一条通路各留一份同一句话的录音——同一位来电者念一个邮编和一个邮箱地址，分别以 8 kHz μ-law 与宽带 Opus 采下来。它花你一个下午，永不过时，而且下一次「是模型还是线路」的争论再起时，它能在大约三十秒内结案。

STEP 6

按 4 kHz 去设计，因为你拿到的就是这个。

接受这道天花板，设计工作就转向在它之下仍然有回报的那些事。把识别器偏置到一个回合里合法可能出现的词汇上——产品名、城市名、那个有限的状态集合——因为一个强先验是唯一能真正替代缺失声学证据的机制。对任何字母数字内容使用标准字母表并回读一次，这是对窄带所造成的那些混淆对唯一可靠的修复。按后果而不是只按置信分数来决定是否确认，好让账号里听错的一位数字代价是再问一次、而不是一次错误转接，做法见语音故障模式。并且记住，噪声与信道失真对一个 4 kHz 信号的伤害不成比例地更大，所以一位开着车载免提的来电者，在编解码之前就已经远低于你的测试条件了。

底层的那个论点值得与这些战术分开说。大多数语音智能体的质量工作，隐含地是在争论模型；而「从演示到部署」之间那道差距里，有相当一部分其实是在争论一根线。频带不是传输层的一个细节，它是你的系统将来所能拥有的证据的一个上界——而那些真去测量它的团队，会停止做那些注定不可能成功的实验。

今天就做这三件事。在你音频通路的每一跳上写下采样率，找出最窄的那一跳。把你完全掌握的每一条腿切到 16 kHz 或更好的 Opus，而 PSTN 那些腿就别动。然后给你的评测集加一列编解码并重跑一遍，这样下一次准确率被质疑时，你能用「每个频带一个数字」来回答，而不是用一次换模型来回答。
